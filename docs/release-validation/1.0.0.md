# ASICEN 1.0.0 検証記録

候補取得、device-free gate、起動/受信、CARD、USB、LNB、soak、cleanupの共通手順は [`../release-validation.md`](../release-validation.md) を正本とする。本書は1.0.0固有matrix、Windows/WinSCard確認、現在までに実証された候補範囲を記録する。

## 1.0.0 初回matrix

このmatrixは1.0.0だけに適用し、後続releaseへ自動継承しない。代表Linux x86_64は2時間、macOS arm64とWindows x86_64は各30分、その他の配布binaryは各10分試験する。各native binaryで短時間回帰し、全地上波channelと無料衛星対象channel（無料CSを含む）を各10秒raw TS取得する。地域・channel・周波数・TSID・slotは試験前に現地計画から固定する。各機種自体の一度以上2時間qualificationとmajor version各OS/architectureの短時間TSも別々に記録する。

## Windows x86_64 / WinSCard

Windows x86_64とWinSCardは1.0.0のnative検証対象である。Windows ZIPは通常release aggregateには含まれないため、候補source SHAに一致する成功済み`build_userland.yml` runの期限付き`win-candidate` artifactを使う。配布aggregateへの未接続は、この検証対象から除外する理由にならない。

```powershell
$D = Join-Path $env:TEMP "asicen-rc-download-$PID"
$PAYLOAD = Join-Path $env:TEMP "asicen-rc-payload-$PID"
New-Item -ItemType Directory -Path $D, $PAYLOAD | Out-Null
gh run view <candidate-run-id> --repo Khronos31/asicen-userland --json headSha,conclusion
gh run download <candidate-run-id> --repo Khronos31/asicen-userland --name win-candidate --dir $D
$ZIP = Get-ChildItem $D -Filter *.zip | Select-Object -First 1
Get-FileHash -Algorithm SHA256 $ZIP.FullName
Expand-Archive -LiteralPath $ZIP.FullName -DestinationPath $PAYLOAD
Set-Location $PAYLOAD
```

runの`headSha`をcandidate source SHAと、conclusionを`success`と照合する。ZIP内checksum、source manifest、provenanceも照合してから、native Windows 11 x64上で次を確認する。

```powershell
.\asicend.exe --help
.\asicen-ts.exe --help
.\asicenctl.exe --help
.\asicend.exe --list-json
```

続けて列挙結果から実際のUSB topologyを選び、対象USB機能が既にlibusb利用可能なdriverであることを確認する。driver自動変更・システム設定変更はしない。READMEの起動形に合わせ、実値へ置き換えた同じ`--instance`と`--runtime-dir`でdaemon、status/list、TS clientを接続する。全地上波・無料衛星targetを各10秒受信した後、同candidateから30分（`--time 1800`）連続受信する。candidate/hash、Windows version/architecture、model/topology、driver/access path、実command、終了値、TS/counters、process/FD/RSSを記録する。

`win-candidate`内のapplication-local `WinSCard.dll`は、Windows nativeのPC/SC API consumerと組み合わせて別に確認する。consumerを候補DLLと同じscratch application directoryから起動し、processがその候補directoryのDLLをロードしたことを確認する。DLLをsystem directoryへ配置したり、global登録・service/driver設定を変更したりしない。context確立、reader列挙、reader/card status、connect、ATR、reset、`90 30 00 00 00` APDU送信、disconnect/context releaseを確認する。物理cardの抜去でremoved/no-card、再挿入後にreader/card接続と操作が復帰することを確認する。公開記録へ生ATR、card ID、APDU response本文を含めない。consumerを用意できない場合は、WinSCard API経路を`未実施`とし、CLI CARD_*の結果で置き換えない。
