実施した2時間capture command:

```sh
asicen-ts --instance qa-fixed-as --runtime-dir /tmp/3pr/asrt \
  --receiver 1 --channel T27 --time 7200 --output /dev/null
```

全channel runではclient continuity counter 0だった一方、独立TS解析でT30に5,359、T31に7,368 continuity discontinuitiesを観測した。原因調査・再試験は未実施のためこの2 channelを判定保留とする。

### Linux musl x86_64 配布candidateの補助受信

ASICEN source `d3582977ea42a12af1175edc53d781e3990bc55c` / Core `154e9de7b813cee3cd9db07f22795a4a9e9ae833`、Actions run `40153002152` の`linux-musl-x86_64` artifact `12584100716`（package SHA-256 `09344d8b74cae831ac3d435fef58fe008f7aa5e1d3ae9f0ab4964b1be671d09c`）をPX-W3U2で8秒→600秒→8秒取得した。W3U2はwarm runtimeだったためdaemon logでfirmware upload skipを確認し、cold uploadは試していない。

10分capture command:

```sh
asicen-ts --device usb:1-2.3.1,1-2.3.2 --instance musl-as --receiver 1 \
  -c T27 -t 600 -o /dev/null --runtime-dir <runtime>
```

実時間601.342秒、client exit 0、6,537,911 packets / 1,229,127,268 bytes、client error counters 0。初回短TSの独立解析はPID 256 discontinuity=1、client continuity counter=0で不一致。事後短TSではdiscontinuity 0だったが、恒常性・原因・閾値は未確定のため初回差を合格扱いにしない。daemon通常終了はexit 0、runtime socketとUSB ownerなし。

このmusl試験はPX-W3U2の単一stream部分実測であり、PX-W3U2自身の初回手順（2時間受信・4番組同時録画と同機種の回帰項目）を満たさない。PX-W3U3のnative archive確認や4番組同時録画/3波/status/反復APDU/CARD・USB/PCSCも満たさず、W3U3の同artifact試験は未実施。両機種それぞれの初回完了には代用しない。

PX-W3U2とPX-W3U3では4番組同時録画が最低要求である。現行実装は同時stream 1本のため要求未達で、1.0.0の既存記録に4番組同時録画の合格実績はない。W3U3の公称4 tuner paths、discoveryの4 route records、公開receiver slot 0/1は別の値であり、4番組同時録画の達成を意味しない。

CARDはstatus present→抜去時 absent→再挿入後ATR/APDU復帰を確認し、初期resetの試行はexit 9だった。PC/SC probeは成功。LNBは0→15→0Vの実測を完了した。一方、停止中USB抜去/再挿入後のcold startでdaemon exit 3となり、sibling USB functionが現れず、T27再取得を行えていない。詳細は[`initial-model-checks.md`](initial-model-checks.md)へ記録する。PX-W3U2の部分実測はPX-W3U3の機種別初回を満たさない。

各OS/ABIのfinal candidate archive回帰、native Windows/WinSCard、最終candidate由来の2時間・全channel結果は未認定。全channel10秒取得はLinux x86_64代表機に限り、各binaryで行う短時間回帰と分ける。

手持ちのASICEN機器にLNB制御非対応profileの実機がないため、T11の非対応profileに対する公開API拒否と物理給電非切替は1.0.0で未実施である。対応機でのLNB実測をこの拒否確認の合格へ代用しない。

## Windows x86_64 / WinSCard

Windows x86_64とWinSCardは1.0.0の検証対象である。native候補取得・展開・USB/daemon/PCSCの再利用手順は [`../release-validation.md`](../release-validation.md) のWindows/PCSC手順へ集約する。Windows ZIPが通常release aggregateに含まれない場合も、同候補の`win-candidate` artifactによるnative確認を省略しない。
