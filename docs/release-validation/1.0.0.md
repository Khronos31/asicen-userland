# ASICEN 1.0.0 検証記録

候補取得、device-free gate、起動/受信、CARD、USB、LNB、連続受信、cleanupの共通手順は [`../release-validation.md`](../release-validation.md) を正本とする。本書は1.0.0で確認できた結果とWindows/WinSCardの未達を記録する。

## 1.0.0 問題発見試験の実績

ASICEN source `d3582977ea42a12af1175edc53d781e3990bc55c` とCore `154e9de7b813cee3cd9db07f22795a4a9e9ae833` のLinux x86_64 local build-qaで、PX-W3U3のT27を2時間連続受信し、全対象channelの短時間TS確認を行った。T27は75,604,838 packets / 14,213,709,544 bytes、client/daemon exit 0、client counters 0、USB pump overflow/discard counters 0。これは最終1.0.0 candidate archiveのnative matrix結果ではない。

実施した2時間capture command:

```sh
asicen-ts --instance qa-fixed-as --runtime-dir /tmp/3pr/asrt \
  --receiver 1 --channel T27 --time 7200 --output /dev/null
```

全channel runではclient continuity counter 0だった一方、独立TS解析でT30に5,359、T31に7,368 continuity discontinuitiesを観測した。原因調査・再試験は未実施のためこの2 channelを判定保留とする。

CARDはstatus present→抜去時 absent→再挿入後ATR/APDU復帰を確認し、初期resetの試行はexit 9だった。PC/SC probeは成功。LNBは0→15→0Vの実測を完了した。一方、停止中USB抜去/再挿入後のcold startでdaemon exit 3となり、sibling USB functionが現れず、T27再取得を行えていない。詳細は[`initial-model-checks.md`](initial-model-checks.md)へ記録する。PX-W3U2の補助試験は標準W3U3の代用ではない。

各OS/ABIのfinal candidate archive回帰、native Windows/WinSCard、最終candidate由来の2時間・全channel結果は未認定。全channel10秒取得はLinux x86_64代表機に限り、各binaryで行う短時間回帰と分ける。

## Windows x86_64 / WinSCard

Windows x86_64とWinSCardは1.0.0の検証対象である。native候補取得・展開・USB/daemon/PCSCの再利用手順は [`../release-validation.md`](../release-validation.md) のWindows/PCSC手順へ集約する。Windows ZIPが通常release aggregateに含まれない場合も、同候補の`win-candidate` artifactによるnative確認を省略しない。
