### 無効な3.853958 ms計測

先行する00:51台のLNB 0 V試行では、開始前と終了後に別々の `python3` を起動し、各 `time.monotonic_ns()` の差から `3.853958 ms` を計算していた。実環境は `/usr/bin/python3`、Python `3.9.6`。macOSでこの時計が全プロセス共通になったのはPython3.10であり、3.9.6実装はプロセス内の基準値を差し引く。そのため **別プロセス間の差はこの試行の経過時間として無効** である。[Python公式文書](https://docs.python.org/3/library/time.html#time.monotonic)、[CPython v3.9.6実装](https://github.com/python/cpython/blob/v3.9.6/Python/pytime.c) を参照。

この誤計測から導いた「約3.85 msで即時TIMEOUT」という途中評価は撤回する。client自体の exit5 / TIMEOUT / 0 packets / 0 bytes とdaemon wait exit0は別の観測として保持する。開始頃00:51:14 UTCとstderr mtime00:51:44 UTCは約30秒と整合するが、mtimeを厳密な経過時間へ置き換えない。旧計測は無効値として残し、上記 `/usr/bin/time -p` と開始終了UTCを保存した再計測と区別する。製品のタイムアウト不具合が確認されたとはしない。
